# Architecture

Blum Studio has three parts: an **engine** that owns the document format, a
**server** that stores designs and exposes them over HTTP and MCP, and a
**UI** (gallery and editor) that runs in the browser. Everything is
TypeScript.

```
MCP client ──stdio──▶ server/mcp ─────┐
                                      ├──▶ ui/engine (validate, apply ops, lint)
browser ─────HTTP────▶ server/routes ─┘
                                              │
                                              ▼
                            server/store.ts ◀──▶ designs/<id>.json
                                              │
                            server/export ──▶ Chromium ──▶ PNG / PDF
                            (same renderer as the browser: ui/render)
```

The engine is the single source of truth. The server and the browser both
import it, so an edit is validated the same way wherever it comes from.

## The document format

```json
{ "version": 1, "name": "…", "format": "story", "background": {…}, "items": […] }
```

- `format` is an id from `ui/engine/formats.ts` (story, post, print sizes), or
  `custom` with `width` and `height` in pixels.
- Each item has an `id`, a `type` (`text`, `shape`, `image`, `sticker`,
  `vector`, `photo`, `group`) and type-specific `props`. A `vector` holds an
  agent-drawn SVG that `ui/engine/vector.ts` checks against a strict allowlist.
- `x` and `y` are the item's **centre** in design pixels. `angle` is clockwise,
  in degrees.
- Colours are `#rrggbb` or `rgba(r,g,b,a)`.
- Group children are positioned relative to the group's centre.

## Repository layout

```
assets/        fonts, stickers, textures, photo catalogue, cut-out model
bin/           the published `blum-studio` entry point (studio, or `mcp` over stdio)
docs/          README images
examples/      the example designs; first launch copies them into the designs dir
scripts/       start, Chromium install, server build, end-to-end MCP check, font CSS and texture colour generators
server/        Node server: HTTP API, MCP server, storage, export
ui/            engine, renderer, gallery and editor
designs/       your designs (git-ignored) from a clone; the npm package uses `~/BlumStudio/designs/` (`BLUM_DESIGNS` overrides both)
```

## `ui/engine/`: the document engine

Pure TypeScript with no DOM. Runs in the browser and in Node.

| Path | Owns |
|---|---|
| `index.ts` | The public API. Everything outside the engine imports from here. |
| `model.ts`, `formats.ts` | Document types; page formats and safe margins. |
| `names.ts` | Rules for colour, shape, pattern and filter names. |
| `sources.ts` | The one image-source rule (media, bundled assets, remote, image data URIs), shared with the render. |
| `validate.ts` | Checks for items and whole documents. |
| `json/` | Reading and writing designs, with defaults. |
| `ops/op.ts`, `ops/apply.ts` | Parsing an op batch and applying it. |
| `ops/kinds/` | One file per op family: items, order, group, align, arrange, look. |
| `ops/fields/` | Field updates, one file per item type. |
| `ops/layout.ts`, `ops/lookup.ts` | Stacks and anchors; finding items and making ids. |
| `geometry.ts` | Boxes and rotation. |
| `vector.ts` | The SVG workshop's allowlist: parses an agent's SVG, refuses anything but shapes, paint and transforms, and re-serialises a clean copy. |
| `lint/` | Colour maths and the design check with its care score (`texture-colours.ts` holds the measured mean of each paper texture). |
| `engine.test.ts`, `vector.test.ts`, `golden/` | The engine test suites and their fixtures. |

## `ui/render/`: the renderer

Turns a design into HTML. The gallery thumbnails, the editor canvas and the
PNG export all use it, so a design looks the same everywhere. Sizes use
container units, so a design scales with its box.

| Path | Owns |
|---|---|
| `render.ts` | `renderDesign`, the entry point. |
| `items/` | One file per item type. `item.ts` dispatches; `text-style.ts` holds what flat and curved text share; `photo.ts` also draws stickers and vectors (a vector is shown as an image, so it can never run code). |
| `shapes/` | Shapes as SVG, and lines with their caps and strokes. |
| `background/` | Page backgrounds and pattern tiles. |
| `colour.ts`, `util.ts`, `types.ts` | Colour validation, escaping and units, prop types. |
| `virtual-grid.ts` | Virtualized tile grid shared by the editor sticker panel and the Resources page. |
| `fonts.css`, `render.css` | Font faces (generated by `scripts/gen-font-css.mjs`) and base styles. |

## `ui/editor/`: the visual editor

Every edit goes through the engine as an op. Drags preview locally and commit
once, on release. The editor polls the design's modification time and reloads
when an agent changes it.

| Path | Owns |
|---|---|
| `editor.ts` | Boot: builds the chrome, opens a design, wires the modules together. |
| `live.ts` | The open design's state and the chrome elements, set once at boot. |
| `state.ts`, `api.ts` | Editor state types; HTTP calls and the ordered save queue. |
| `commits.ts`, `render-loop.ts` | Applying edits locally then on the server; repainting. |
| `actions/` | Commands on the design, the selection and text style. |
| `keyboard.ts`, `icons.ts` | Shortcuts; Lucide icons. |
| `chrome/` | Top bar, side rail, zoom, sliders. |
| `canvas/` | Stage, viewport, rulers, selection overlay, workspace hit-testing. |
| `gestures/` | Pointer handling: `dispatch.ts` routes a press to move, resize, rotate, line, marquee or double-click. |
| `geometry/` | Boxes, snapping, angles, line handles. |
| `text/` | Measuring text and fitting it to its box. |
| `toolbar/` | The contextual toolbar, one file per section. |
| `panels/` | Side panels: text, shapes, stickers, images, layers, review, background. |
| `overlays/` | Menus, context menu, dialogs (`dialogs.ts`: house confirm and prompt), banner, inline text editing, start screen. |
| `styles/` | Editor CSS, one file per area. |

`toolbar/`, `panels/` and `overlays/` each have a `hooks.ts`. It holds the
callbacks the editor passes in at boot, so a section never imports the
editor back.

## `ui/gallery/`: the app pages

| Page | URL | Script |
|---|---|---|
| `create.html` | `/` | `create.ts`: prompt, formats, attached photos and documents (PDF, text), agent picker |
| `session.html` | `/create/<id>` | `session/`: the agent run, its live transcript and design previews |
| `designs.html` | `/designs` | `designs/`: `gallery.ts`, with `list.ts`, `cards.ts`, `thumbnails.ts`, `delete.ts`, `create-design.ts` |
| `resources.html` | `/resources` | `resources.ts` |
| `settings.html` | `/settings` | `settings.ts`: detect and connect AI agents |
| `getting-started.html` | `/getting-started` | `getting-started.ts` |

`designs/recents.ts` fills the sidebar's recent sessions on every page. `theme.css`
holds the colour and shape tokens shared with the editor. `styles/` has one
file per page, plus `shell.css` for the sidebar and buttons.

## `ui/cutout/`

Background removal with the U²-Net small model on onnxruntime-web. Used by
the editor's photo toolbar and, through Chromium, by the MCP `import_image`
tool.

## `server/`

| Path | Owns |
|---|---|
| `main.ts` | Boot, static files and the route table. Listens on `127.0.0.1:${BLUM_PORT}` (8092 by default). |
| `http.ts`, `paths.ts` | Request and response helpers; where designs, assets and builds live. |
| `version.ts` | The studio version, read from the root `package.json` (one source of truth). |
| `store.ts` | Reading, writing and listing designs, validated both ways, with a per-design write lock. |
| `histories.ts` | Undo and redo on disk, shared by HTTP and MCP. |
| `resources.ts` | Fonts, stickers, photos and masks, for both APIs. |
| `lint.ts` | The engine's design check, with text overflow measured on the real fonts. |
| `sessions.ts` | Create-page sessions, stored in `designs/.sessions/`. |
| `routes/` | HTTP endpoints: designs, ops, media, export, resources, agents, and `console/` for agent runs. |
| `mcp/main.ts` | The MCP server and its tool table. |
| `mcp/trust.ts` | Argument checks shared by every tool: ids, paths, sticker refs. |
| `mcp/tools/` | Tool implementations, one file per group (`vector.ts` is the `draw_svg` workshop). |
| `mcp/compact.ts`, `mcp/item-examples.ts` | Short text replies; one valid example per item type. |
| `export/` | One shared Chromium (downloaded on first launch or export, never with the install); PNG, PDF, text measurement, background removal. |
| `agents/` | Detecting and connecting AI agents (Claude Code, Codex, Muse, Claude Desktop, Cursor), and running Claude Code for the Create page. |
| `node.d.ts` | Minimal Node type declarations, so the server builds without `@types/node`. |
| `test/` | The server suite (`node:test`), one file per route group and MCP group, plus `i18n` (resources stay English) and `csrf` (cross-site write guard). |

`scripts/build-server.mjs` bundles the server into `server/dist/`: `server.js`,
`mcp.js` and `connect.js`.

## Security

- The server listens on `127.0.0.1` only.
- Routes that change state or start a process need the `X-Blum-Request: 1`
  header and a local `Origin`, which blocks requests from other websites.
- Agent processes get their prompt as a single argument and never go through
  a shell. On the Create page, Claude Code may only use the Blum MCP tools.
- Every MCP argument and every HTTP body is validated before it reaches the
  engine or the disk.
